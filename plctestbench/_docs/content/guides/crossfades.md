# Crossfades in the Python API

Crossfades smooth the boundaries between received audio and audio generated by a packet-loss concealment (PLC) algorithm. They are configured on a PLC algorithm's settings object; you do not run a crossfade as a separate testbench worker.

Every `PLCSettings` subclass exposes two transitions:

- `fade_in` blends recent reconstructed context into the PLC prediction at the start of a lost packet.
- `crossfade` blends the continuing PLC prediction into received audio when valid packets resume.

Both default to `NoCrossfadeSettings`, so creating an algorithm settings object without either argument preserves the unblended behavior.

## Choose a crossfade setting

Import crossfade settings and enums from `plctestbench.settings`.

| Class | Curve | Configurable values |
| --- | --- | --- |
| `NoCrossfadeSettings` | Disabled (zero length) | None |
| `LinearCrossfadeSettings` | Power function, exponent 1 | `length`, `type` |
| `QuadraticCrossfadeSettings` | Power function, exponent 2 | `length`, `type` |
| `CubicCrossfadeSettings` | Power function, exponent 3 | `length`, `type` |
| `SinusoidalCrossfadeSettings` | Sine from 0 to π/2 | `length`, `type` |
| `ManualCrossfadeSettings` | Power or sinusoidal | `length`, `function`, `exponent`, `type` |

`length` is measured in **milliseconds** and defaults to `10` in the Python convenience classes. At runtime it is converted to samples using the source track's sample rate.

### Curve function and exponent

`CrossfadeFunction` controls the incoming signal's gain curve:

- `CrossfadeFunction.power` uses `x ** exponent` for `x` from 0 to 1.
- `CrossfadeFunction.sinusoidal` uses `sin(x)` for `x` from 0 to π/2.

The `exponent` matters for the power function: `1` is linear, `2` is quadratic, and `3` is cubic. The named convenience classes set these values for you.

### Mixing type

`CrossfadeType` determines the complementary gain applied to the outgoing signal:

- `CrossfadeType.power` uses `sqrt(1 - incoming_gain²)`, maintaining complementary squared gains.
- `CrossfadeType.amplitude` uses `1 - incoming_gain`, maintaining complementary linear gains.

The default is `CrossfadeType.power`.

## Configure a full-band crossfade

Pass a single crossfade settings object to the PLC settings constructor. It is normalized internally to a one-element list.

```python
from plctestbench.plc_algorithm import BurgPLC
from plctestbench.settings import (
    BurgPLCSettings,
    CrossfadeType,
    LinearCrossfadeSettings,
    SinusoidalCrossfadeSettings,
)

settings = BurgPLCSettings(
    fade_in=LinearCrossfadeSettings(
        length=2,
        type=CrossfadeType.amplitude,
    ),
    crossfade=SinusoidalCrossfadeSettings(
        length=8,
        type=CrossfadeType.power,
    ),
    context_length=100,
    order=16,
)

plc_algorithms = [(BurgPLC, settings)]
```

In this example, a 2 ms linear fade introduces each prediction and an 8 ms sinusoidal transition returns to received audio.

!!! important "Fade-in length"

    The algorithm initializer requires the numeric `fade_in.length` value to be no greater than the inherited `packet_size`; otherwise it raises `ValueError`. Use one `fade_in` setting—only the first list entry is used.

## Define a custom curve

Use `ManualCrossfadeSettings` when the named presets do not provide the required combination.

```python
from plctestbench.settings import (
    CrossfadeFunction,
    CrossfadeType,
    ManualCrossfadeSettings,
    ZerosPLCSettings,
)

settings = ZerosPLCSettings(
    crossfade=ManualCrossfadeSettings(
        length=6,
        function=CrossfadeFunction.power,
        exponent=1.5,
        type=CrossfadeType.power,
    )
)
```

`length` and `exponent` must be non-negative.

## Configure frequency-dependent crossfades

A PLC algorithm can use a different return crossfade for each frequency band. Set:

1. `crossfade_frequencies` to strictly increasing crossover frequencies in hertz;
2. `crossfade` to one setting per resulting band, ordered from low to high; and
3. `crossover_order` to the crossover-filter order.

The number of `crossfade` entries must equal `len(crossfade_frequencies) + 1`.

```python
from plctestbench.settings import (
    CubicCrossfadeSettings,
    LinearCrossfadeSettings,
    NoCrossfadeSettings,
    ZerosPLCSettings,
)

settings = ZerosPLCSettings(
    crossfade_frequencies=[200, 2000],
    crossfade=[
        LinearCrossfadeSettings(length=8),   # below 200 Hz
        CubicCrossfadeSettings(length=5),    # 200–2000 Hz
        NoCrossfadeSettings(),               # above 2000 Hz
    ],
    crossover_order=4,
)
```

Crossovers must be between 0 and 20,000 Hz according to settings validation. For processing to succeed, each value must also be greater than 0 and below half the source track's sample rate.

Frequency-dependent processing applies to `crossfade`, not `fade_in`; `fade_in` uses one full-band setting.

### Change frequencies immutably

`set_crossfade_frequencies()` returns a cloned settings object, preserves existing entries by position, appends `NoCrossfadeSettings` for new bands, and trims entries when bands are removed.

```python
base = ZerosPLCSettings(crossfade_frequencies=[1000])
expanded = base.set_crossfade_frequencies([1000, 3000])

assert base.get("crossfade_frequencies") == [1000]
assert len(expanded.get("crossfade")) == 3
```

Review appended entries after expanding the list, because new bands have no crossfade by default.

See [`plctestbench.settings`](../reference/settings.md) for constructor signatures and [`plctestbench.crossfade`](../reference/crossfade.md) for the processing implementation.
